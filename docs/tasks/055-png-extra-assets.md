Design (Claude's call):

1. Import (`index.ts`). Decode each extra asset's base64 text into real bytes with a small local `base64ToBytes` helper (strip whitespace, `atob` loop, the same style as `tryExtractAvatarImage` in the same file). Store the bytes under the full chunk keyword, `chara-ext-asset_:{path}`, instead of the bare `path`. Reason: the prefix makes these entries recognisable on export without a schema change, and it matches the form `converter.ts` and `galleryUtils.ts` already test with `startsWith('chara-ext-asset_:')`. A chunk whose text is not valid base64 is skipped and a warning is added: `Extra PNG asset "{path}" is not valid base64 and was skipped.` (put it in the same `warnings` list the import already returns; keep returning `undefined` when the list is empty). Cards already stored keep their old bare keys and their corrupted bytes; there is no migration in this card (Claude logs it).
2. `writeCardToPng` (`png.ts`). `WritePngOptions` gets `extraAssets?: Record<string, Uint8Array>`, keyed by the bare `path`. When the option is passed (even empty), `writeCardToPng` first removes every tEXt chunk whose keyword starts with `chara-ext-asset_:` from the base PNG (together with the existing `ccv3` and `chara` removal), then writes one tEXt chunk per entry, in ascending key order, keyword `chara-ext-asset_:{path}`, text = base64 of the bytes, inserted right after the `ccv3` chunk (and the `chara` chunk with `backfillV2`), so before the first IDAT. When the option is not passed, nothing changes: the base PNG's chunks stay. Bytes to base64 needs a local helper in `png.ts` that converts in slices (for example 0x8000 bytes per `String.fromCharCode` call, then one `btoa`) so a large asset cannot overflow the call stack; do not use `utf8ToBase64` for bytes. If an asset's base64 text is longer than `MAX_PAYLOAD_SIZE` (the reader refuses such a chunk), throw `Error` naming the path ("Extra asset \"{path}\" is too large to embed in a PNG."). A clear error beats a file this app cannot read back and beats silently dropping the asset.
3. `exportCardData` (`index.ts`), PNG branch. Build `extraAssets` from `options.embeddedAssets`: the entries whose key starts with `chara-ext-asset_:`, with the prefix removed. Pass `extraAssets` to `writeCardToPng` only when at least one such entry exists; otherwise pass nothing, so a card that holds no extra-asset entry (including every card stored before this change) keeps today's behaviour and its base PNG's chunks stay.
