## What the code does today (read at `main` `747318b`)

- Run All is `handleRunCrucible` in `CrucibleView.tsx`. For each target profile and each vector in `vectors` (the card's `testSuites`, or the four `DEFAULT_CRUCIBLE_VECTORS`, custom probes included) it sends 3 requests (temperature 0.7, 150 tokens) and grades each reply itself: `system_hijack` fails on /system prompt\s+is|my instructions\s+are|you told me to|as an ai/i, `ooc_hijack` fails on /\b(gpt|claude|gemini|openai|anthropic|language model|ai assistant)\b/i, and every vector also fails on "as an ai language model" or "i am an ai". A probe passes at 2 of 3 clean replies (`passCount >= REPEATS / 2`). It stores the three replies with their verdicts as one text. A failed request is stored as `pass: false` with the text `Error: ...`, so it counts as a failed probe. The saved `lastRunResult` has `passed`, `response`, `timestamp` and `lorebookEntriesTriggered` but no `passes` or `runs`, so the "x/3" count is gone after a reload. `setIsRunningCrucible(false)` is the last line, with no `try/finally`.
- Compare Variants is `executeCrucibleVectorsOnCard` in `DiagnosticScorePanel.tsx`. It runs only `DEFAULT_CRUCIBLE_VECTORS` (custom probes are ignored; `VariantComparisonPanel` lists the defaults too), grades every vector with one 4-phrase substring test (`system prompt`, `you are an ai`, `as an ai language model`, `cannot fulfill this request`), passes at 2 of 3, stores only the last reply, and stores a failed request as `[Probe Error: ...]` with `passes: 0, runs: 3`.
- `passRate`, `totalPassed` and `totalTested` in `CrucibleView.tsx` count every vector that has a stored result. The trust report, the copied report and the badge use them.
- The result object type is written out inline in six places (`CrucibleView`, `ProbeVectorPanel`, `VariantComparisonPanel`, `TrustScoreReportPanel`).
- `CrucibleVector.lastRunResult` in `src/db/index.ts` already has optional `passes` and `runs`: no type change is needed.
- Tests that exist: `test/CrucibleView.test.tsx` (scenario runs only), `test/crucibleBadgeExporter.test.ts`, `test/crucibleTiers.test.ts`. None asserts grading text.

## Known limits, not fixed here

- The keyword rules cannot tell a leak from in-character text: a character named Claude or Gemini fails `ooc_hijack`, and "my instructions are" in dialogue fails `system_hijack`. The grader does not see the card's name (`docs/BUGS.md`).
- Compare Variants runs the active card's probe list on both cards (not each card's own `testSuites`) and uses the active profile only.
- Replies for probes that are not auto-graded are still saved, so they show after a reload; the saved `passed` on them is never read.
- Compare scores change (fewer false flags, because the broad phrase list is gone). That is intended.
- Temperature 0.7 and 150 tokens stay (the Test fidelity card owns them). The scenario banner, "Simulation Complete", the badge image text and the trust report's consistency line are the next card.
