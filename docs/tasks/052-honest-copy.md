**C. Bulk ZIP export keeps cards that share a file name.**
- Verified (`docs/BUGS.md`; re-read by Claude at `4b88825`): `handleBulkExportAllZip` and `handleBulkExportSelectedZip` in `GalleryView.tsx` build the name as `cardRecord.name.replace(/[^a-z0-9_-]/gi, '_') || 'card'` plus the extension and call `zip.file(filename, bytes)`. A second card with the same sanitized name replaces the first in the ZIP. Every character outside a-z, 0-9, `_` and `-` becomes `_`, so two names written in Japanese or Cyrillic collide. The toasts count `cards.length` and `targetUuids.length`, not the files written; the selected version skips a uuid it does not find in `cards` but still counts it.
- New `src/utils/zipFileNames.ts` exporting `uniqueZipFileName(name: string, ext: string, used: Set<string>): string`. It sanitizes `name` with the rule above (unchanged; non-ASCII stays `_`) and forms `${base}.${ext}`. Names are compared case-insensitively (the lowercase name is the key in `used`), because Windows and macOS extract case-insensitively. If the key is taken it tries `${base}_2.${ext}`, `${base}_3.${ext}` and so on until one is free. It adds the chosen name's lowercase key to `used` and returns the name. A first use returns the name unchanged.
- In both handlers: create `const usedNames = new Set<string>()` and `let writtenCount = 0` before the loop; replace the `filename` line with `uniqueZipFileName(cardRecord.name, ext, usedNames)`; add 1 to `writtenCount` after each `zip.file`. The success toasts use `writtenCount` for the number and the plural `s`; their other wording stays ("Exported all N card(s) to ZIP archive (FMT)." and "Exported N selected card(s) to ZIP archive (FMT)."). The download and the cover-omitted toast stay as they are.
- Not in this card: keeping non-ASCII letters in file names; the word "selected" in the toast when nothing is selected (the handler then exports every card); what happens when one card fails to export.
