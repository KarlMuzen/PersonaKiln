- **Merge restore can roll back newer local edits and erase a saved API key (verified in the code 2026-11-01 at `main` `e6fefc2`; carded as 042).** `restoreFullBackup` in `src/io/backup.ts`; the Settings button only ever restores in merge mode (`BackupRestoreSection.tsx`). (1) For a card with the same `uuid`, `merge` and `overwrite` both call `db.cards.update` with the backup's `name`, `tags`, `creator`, dates, `order`, `cardData`, `embeddedAssets` and `snapshots`, with no date comparison, so an older backup replaces newer local work including its snapshot list; the update does not write `testSuites`, `scenarios`, `variantOf`, `variantLabel` or `avatarUrl`, so a replaced card keeps the local copies of those. (2) Lorebooks have the same rollback (`updatedAt` is never compared); this was missing from this list before. (3) For an existing profile, a keyless backup (`apiKeyRedacted`) or an undecryptable `enc.v1.` key sets `rec.apiKey = undefined` and passes it to `db.connectionProfiles.update`; Dexie treats `undefined` in an update as a delete, so the local key would be erased. Inferred, not run; card 042 starts with a test. (4) In merge mode every incoming setting that is not a device security key is written with `db.settings.put`, so older assistant chats and editor undo history replace local ones. (5) Stored card dates are Unix seconds in the app (`cardSlice.ts`, `useCardStore.ts`), imported cards can carry milliseconds, and the existing backup tests use `Date.now()`; card 042 compares both in seconds. The restore dialog says "Database restored! Restored N cards, ..." and does not say what was kept. The smoke test's round trip (card 040) restores into an empty Library and does not cover these cases. Not fixed by 042: when the backup copy wins its snapshot list replaces the local one; the local undo history of that card stays; edits to test suites, scenarios, snapshots and card order do not bump `modification_date` (`updateActiveCardTestSuites`, `updateActiveCardScenarios`, `createSnapshot`, `reorderCards` in `cardSlice.ts`), so a tie keeps the local copy and a restore does not carry such edits across.

The Dexie hooks in `src/db/index.ts` run the strict storage schemas on every add and update and throw past a limit. Import reads cards with the loose schema, so a card can be read and then fail at save; an autosave that fails shows "Save failed" (`saveActiveCardMetadata`). Unverified: how many real cards exceed a cap, what the import screen shows, whether the editor fields have their own length limit. Needs a real-card fixture.
